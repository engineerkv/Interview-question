### 121. 🔵 How does JWT authentication work?

**🧠 Concept**

JWT (JSON Web Token) is a stateless authentication method that encodes user information in a signed token for secure API access.

**💻 Example**

```javascript
// JWT token creation
const jwt = require('jsonwebtoken');
const secret = 'your-secret-key';

const token = jwt.sign(
  { userId: 123, email: 'user@example.com' },
  secret,
  { expiresIn: '1h' }
);

// JWT token verification
const verifyToken = (req, res, next) => {
  const token = req.headers.authorization?.split(' ')[1];
  
  try {
    const decoded = jwt.verify(token, secret);
    req.user = decoded;
    next();
  } catch (error) {
    res.status(401).json({ error: 'Invalid token' });
  }
};
```

**💬 Explanation + Insight**

- **Stateless** - No server-side session storage needed
- **Self-contained** - Token contains user information
- **Signed** - Prevents tampering with token data
- **Expiration** - Tokens expire for security
- **Use Cases** - API authentication, microservices

### 122. 🔵 OAuth2 vs OpenID Connect — what's the difference?

**🧠 Concept**

OAuth2 is an authorization framework, while OpenID Connect is an authentication layer built on top of OAuth2.

**💻 Example**

```javascript
// OAuth2 - Authorization only
const oauth2Flow = {
  clientId: 'your-client-id',
  redirectUri: 'https://yourapp.com/callback',
  scope: 'read:user',
  responseType: 'code'
};

// OpenID Connect - Authentication + Authorization
const oidcFlow = {
  clientId: 'your-client-id',
  redirectUri: 'https://yourapp.com/callback',
  scope: 'openid profile email',
  responseType: 'code',
  nonce: 'random-nonce-value'
};
```

**💬 Explanation + Insight**

- **OAuth2** - Authorization framework, access to resources
- **OpenID Connect** - Authentication protocol, user identity
- **Scopes** - OAuth2 for resource access, OIDC for identity
- **Tokens** - OAuth2 access tokens, OIDC ID tokens
- **Use Cases** - OAuth2 for API access, OIDC for user login

### 123. 🔵 What is PKCE and when is it used?

**🧠 Concept**

PKCE (Proof Key for Code Exchange) adds security to OAuth2 authorization code flow for public clients like mobile apps.

**💻 Example**

```javascript
// PKCE implementation
const crypto = require('crypto');

// Generate code verifier and challenge
const codeVerifier = crypto.randomBytes(32).toString('base64url');
const codeChallenge = crypto
  .createHash('sha256')
  .update(codeVerifier)
  .digest('base64url');

// Authorization request with PKCE
const authUrl = `https://auth.example.com/authorize?` +
  `client_id=your-client-id&` +
  `redirect_uri=https://yourapp.com/callback&` +
  `code_challenge=${codeChallenge}&` +
  `code_challenge_method=S256&` +
  `response_type=code`;

// Token exchange with code verifier
const tokenResponse = await fetch('https://auth.example.com/token', {
  method: 'POST',
  body: JSON.stringify({
    grant_type: 'authorization_code',
    code: authorizationCode,
    code_verifier: codeVerifier,
    client_id: 'your-client-id'
  })
});
```

**💬 Explanation + Insight**

- **Security Enhancement** - Prevents authorization code interception
- **Public Clients** - Essential for mobile and SPA applications
- **Code Verifier** - Random string generated by client
- **Code Challenge** - SHA256 hash of code verifier
- **Use Cases** - Mobile apps, single-page applications

### 125. 🔵 What is mTLS (Mutual TLS) and why is it important?

**🧠 Concept**

mTLS requires both client and server to authenticate each other using certificates, providing stronger security than one-way TLS.

**💻 Example**

```javascript
// mTLS server configuration
const https = require('https');
const fs = require('fs');

const serverOptions = {
  key: fs.readFileSync('server-key.pem'),
  cert: fs.readFileSync('server-cert.pem'),
  ca: fs.readFileSync('ca-cert.pem'),
  requestCert: true,
  rejectUnauthorized: true
};

const server = https.createServer(serverOptions, (req, res) => {
  const clientCert = req.connection.getPeerCertificate();
  console.log('Client certificate:', clientCert.subject);
  res.end('Hello from mTLS server');
});

// mTLS client configuration
const clientOptions = {
  key: fs.readFileSync('client-key.pem'),
  cert: fs.readFileSync('client-cert.pem'),
  ca: fs.readFileSync('ca-cert.pem')
};

const client = https.request({
  hostname: 'server.example.com',
  port: 443,
  path: '/',
  method: 'GET',
  ...clientOptions
});
```

**💬 Explanation + Insight**

- **Mutual Authentication** - Both client and server authenticate
- **Certificate-based** - Uses X.509 certificates
- **Stronger Security** - Prevents man-in-the-middle attacks
- **Use Cases** - Microservices, API security
- **Implementation** - Requires certificate management

### 127. 🔵 How do you prevent XSS, CSRF, and SQL injection?

**🧠 Concept**

Prevent common web vulnerabilities: XSS with input sanitization, CSRF with tokens, SQL injection with parameterized queries.

**💻 Example**

```javascript
// XSS prevention
const validator = require('validator');
const xss = require('xss');

const sanitizeInput = (input) => {
  return xss(validator.escape(input));
};

// CSRF prevention
const csrf = require('csurf');
const csrfProtection = csrf({ cookie: true });

app.use(csrfProtection);

// SQL injection prevention
const db = require('pg');
const client = new db.Client();

// Bad - vulnerable to SQL injection
// const query = `SELECT * FROM users WHERE id = ${userId}`;

// Good - parameterized query
const query = 'SELECT * FROM users WHERE id = $1';
const result = await client.query(query, [userId]);
```

**💬 Explanation + Insight**

- **XSS** - Sanitize user input, use CSP headers
- **CSRF** - Use CSRF tokens, same-site cookies
- **SQL Injection** - Use parameterized queries
- **Input Validation** - Validate and sanitize all inputs
- **Use Cases** - Web applications, APIs

### 129. 🔵 What is zero-trust architecture in microservices?

**🧠 Concept**

Zero-trust architecture assumes no implicit trust, requiring authentication and authorization for every request between services.

**💻 Example**

```javascript
// Zero-trust service communication
const serviceAuth = {
  // Every service call requires authentication
  callService: async (serviceName, endpoint, data) => {
    const token = await getServiceToken(serviceName);
    return await fetch(`${serviceName}/api/${endpoint}`, {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${token}`,
        'Content-Type': 'application/json'
      },
      body: JSON.stringify(data)
    });
  },
  
  // Service-to-service authentication
  authenticateService: (req, res, next) => {
    const token = req.headers.authorization?.split(' ')[1];
    if (!validateServiceToken(token)) {
      return res.status(401).json({ error: 'Unauthorized' });
    }
    next();
  }
};
```

**💬 Explanation + Insight**

- **No Implicit Trust** - Every request authenticated
- **Service Identity** - Services have identities
- **Network Segmentation** - Isolate service networks
- **Least Privilege** - Minimum required permissions
- **Use Cases** - Microservices, cloud-native applications

### 131. 🔵 What is the difference between RBAC and ABAC?

**🧠 Concept**

RBAC (Role-Based Access Control) uses roles, while ABAC (Attribute-Based Access Control) uses attributes for access decisions.

**💻 Example**

```javascript
// RBAC implementation
const rbac = {
  roles: {
    admin: ['read', 'write', 'delete'],
    user: ['read'],
    guest: ['read']
  },
  checkAccess: (userRole, action) => {
    return rbac.roles[userRole]?.includes(action);
  }
};

// ABAC implementation
const abac = {
  policies: [{
    subject: { department: 'HR' },
    resource: { type: 'employee_data' },
    action: 'read',
    condition: { time: 'business_hours' }
  }],
  checkAccess: (user, resource, action, context) => {
    return abac.policies.some(policy => 
      policy.subject.department === user.department &&
      policy.resource.type === resource.type &&
      policy.action === action &&
      policy.condition.time === context.time
    );
  }
};
```

**💬 Explanation + Insight**

- **RBAC** - Simple, role-based permissions
- **ABAC** - Flexible, attribute-based permissions
- **Complexity** - ABAC more complex but flexible
- **Use Cases** - RBAC for simple systems, ABAC for complex requirements
- **Implementation** - RBAC easier to implement
